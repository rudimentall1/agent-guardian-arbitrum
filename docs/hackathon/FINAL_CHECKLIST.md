## Demo Scenario

1. Owner registers an agent (EIP-712 signed).
2. Owner creates a policy authorizing specific (target, selector) pairs
   and/or native-transfer targets, with a daily limit and approval
   threshold.
3. Agent signs an execution intent; a relayer submits it to
   `AgentExecutionGuard.execute` (or `executeFromWallet`, if funded via
   `AgentSmartWallet`).
4. Guard verifies signature, nonce, deadline, policy authorization, and
   spending limits before forwarding the call.
5. Owner (or a designated recovery guardian) can pause the agent or
   trigger emergency recovery at any time, independent of the agent's
   own key.

## Security Goal

Prevent unauthorized autonomous agent actions, with a deterministic,
auditable on-chain boundary — not an AI-mediated one.

The protocol provides:

- identity layer (`AgentRegistry`)
- policy layer (`PolicyRegistry`)
- execution layer (`AgentExecutionGuard`)
- custody layer (`AgentSmartWallet`)
- recovery layer (guardian-controlled emergency disable)

## Current Limitations

This is a hackathon prototype. Known gaps, in priority order:

- No off-chain AI/risk-advisory service (deterministic on-chain rules only)
- No Robinhood Chain support
- No real fuzzer (Foundry/Echidna) run yet
- No independent security review / audit
- No multi-guardian consensus or DAO-based recovery
- No hardware-wallet integration
- No zero-knowledge policy proofs
- No production monitoring/alerting
